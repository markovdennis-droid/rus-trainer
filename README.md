# Тренажёр ЕГЭ по русскому языку — прототип

Кликабельный прототип тренажёра для подготовки к ЕГЭ по русскому языку.
Формат — по демоверсии ФИПИ 2027 года. Пять основных страниц, без сервера и обязательной сборки:
открываются как обычные HTML-файлы.

**Это макет для обсуждения, а не рабочая версия.** Оплата и ИИ имитируются. Работы, проверки, доступ и черновик
сохраняются в localStorage этого браузера; на другое устройство не передаются.

## Что внутри

| Файл | Что это |
|---|---|
| `index.html` | Главная страница: что за продукт, как проверяется сочинение, тарифы |
| `join.html` | Приглашение от преподавателя: имя, оплата, код доступа |
| `student.html` | Кабинет ученика: доступ, варианты, работы, проверенное сочинение |
| `trainer.html` | Тренажёр: вариант на 27 заданий, два режима, проверка сочинения |
| `teacher.html` | Кабинет преподавателя: журнал, приглашения, проверка грамотности |
| `bank/db.js` | Общее хранилище кабинетов — **макет вместо сервера** |
| `bank/` | Матрица КИМ, варианты и языковой инвентарь — см. `bank/README.md` |
| `tools/` | Сборка вариантов, валидатор, извлечение инвентаря |

Вариант лежит данными в `bank/variants/v1.json`, а не в коде страницы:
новые варианты добавляются без правки HTML.

## Как посмотреть

Скачать репозиторий и открыть `index.html` в браузере. Все три страницы
должны лежать в одной папке — ссылки между ними относительные.

Либо включить GitHub Pages: **Settings → Pages → Source: main / root**.
Файл `.nojekyll` уже лежит в корне, чтобы Pages отдавал страницы как есть.

## Путь целиком: преподаватель → ученик → проверка

Этот путь работает в макете от начала до конца.

1. `teacher.html` → **«Добавить ученика»**. Две ссылки на выбор:
   «для группы» — одна на всех, ученик вписывает имя сам;
   «персональное приглашение» — имя вписывает преподаватель, и ученик
   появляется в журнале сразу со статусом «приглашён, не оплатил».
2. Ученик открывает ссылку (`join.html`), видит, кто его приглашает,
   цену со скидкой по приглашению, платит (макет ЮKassa) и получает код.
3. Он попадает в `student.html`: код доступа, предмет, преподаватель,
   список вариантов, его работы.
4. Решает вариант в тренажёре — тот узнаёт ученика по сессии — и
   нажимает **«Сдать работу преподавателю»**.
5. Работа появляется у преподавателя со счётчиком «ждёт проверки».
   Он ставит К7–К10 по шкале и выделяет фрагменты мышью.
6. После «Завершить проверку» ученик видит в своём кабинете итоговый
   балл, баллы по всем критериям и замечания в тексте.

Роли живут в одном браузере, поэтому сессии разведены: вход
преподавателем не выбивает ученика.

## Маршрут по тренажёру

1. С главной — «Открыть вариант».
2. В тренажёре переключить **Экзамен / Тренировка** на заданиях 10 и 16:
   в тренировке буквы вставляются прямо в слово, запятые ставятся кликом
   по месту в предложении, проверка идёт по каждой позиции отдельно.
3. Кнопка **«Матрица КИМ»** в левой колонке — все 27 линий с типом ответа,
   баллом и правилами проверки.
4. Задание 27: написать текст, нажать **«Виртуальный учитель»** — текст
   размечается по предложениям, считаются К1–К6.
5. **«Завершить» → «Сдать работу преподавателю»** — работа уходит
   в кабинет (сохраняется в общем хранилище браузера, сервер не нужен).
6. В кабинете открыть работу: часть 1 свёрнута, сочинение размечено
   машиной, преподаватель ставит К7–К10 по шкале «ошибок нет / 1–2 /
   3–4 / 5 и больше». Выделение фрагмента мышью добавляет замечание.

## Работа с вариантами

```
python3 -I tools/build_variants.py                      # JSON -> JS для браузера
python3 -I tools/validate_variant.py bank/variants/v1.json
```

Валидатор сверяет вариант с матрицей: тип ответа, баллы, ссылки на
несуществующие варианты и предложения, сумму 28 + 22 = 50.

## Структура экзамена (демоверсия 2027)

- Часть 1 — задания 1–26, **28 первичных баллов**
- Часть 2 — задание 27 (сочинение), **22 балла**
- Итого **50 первичных баллов**, 210 минут

### Правила проверки, зашитые в прототип

- Задания 1–7, 9–21, 23–26 — 1 балл, только полное совпадение с эталоном
- Задания 8 и 22 — 2 балла; 1 балл, если неверны одна или две позиции;
  порядок символов важен
- В заданиях 2–4, 9–21, 23, 24, 26 порядок записи символов не важен
- Символов в ответе больше, чем в эталоне, — 0 баллов
- Сочинение меньше 150 слов — 0 по всем критериям

### Проверка сочинения

Машина закрывает К1–К6 — содержание и речевое оформление, **10 баллов**.
Грамотность (К7–К10) — **12 баллов** — ставит человек: нейросеть
не считает орфографические и пунктуационные ошибки в чужом тексте
надёжно, она только подсвечивает подозрительные места.

Модель получает пронумерованные предложения и возвращает номера, а не
цитаты. Границы предложений, в проектируемом продукте подсчёт слов и итоговый балл считает сервер. В демо всё выполняется в браузере.
Посмотреть обмен можно в тренажёре: под разметкой сочинения есть блок
«Что уходит в модель и что приходит обратно».

## Содержание заданий

Все задания и тексты в прототипе **авторские**. Из демоверсии ФИПИ взяты
только структура, баллы и правила оценивания — это документ, а не объект
охраны. Задания из открытого банка ФИПИ и сборников не используются.

Планирование банка и языковой инвентарь (ударение, паронимы, формы
слова) — в `bank/`. Там же разобрано, что из готовых сборников брать
можно, а что нельзя.

## Нерешённые вопросы

1. **Классические тексты.** Решено брать авторов из общественного
   достояния (умерших до 1956 г.). В варианте 1 тексты пока свои:
   достать классику дословно из рабочей среды не удалось. Подробнее —
   в `bank/variants/README.md`. Заменяются только тексты и задания
   1–3 и 23–27; задания 4–22 от текста не зависят.
2. **Кто проверяет сочинение у ученика без репетитора.** Базовый доступ
   даёт автопроверку 1–26; проверка 27-го — платная опция, но
   грамотность (12 баллов из 22) всё равно требует человека.
3. **Объём банка к запуску.** Ориентир — 30 вариантов, то есть около
   780 заданий части 1 и 30 текстов.

## Что здесь макет, а не продукт

`bank/db.js` подменяет собой сервер: держит преподавателей, учеников,
оплаты и работы в хранилище браузера. Этого хватает, чтобы пройти весь
путь и обсудить его, но продавать на этом нельзя:

- **Ключи заданий лежат в `bank/variants/v1.js`** и доступны ученику
  через исходный код страницы. В продукте сервер отдаёт вариант без
  ключей, ответы уходят на сервер, проверка считается там. Логика уже
  описана в `tools/validate_variant.py` — её нужно перенести на сервер.
- Оплата нарисована: настоящая идёт через ЮKassa на стороне банка.
- Нет входа по паролю, восстановления доступа, привязки к устройству.
- Данные живут в браузере: другой компьютер их не увидит.
- Разметка «Виртуального учителя» подставлена, модель не вызывается.

Чего нет совсем: остальных 29 вариантов банка, аудиокомментариев
преподавателя, статистики по западающим темам, выплат партнёрам
(по решению — вручную, по реестру).

## Сборка 13 октября

Сценарий показа — в [HOW-TO.md](HOW-TO.md) и [guide.html](guide.html). План переноса на сервер — в [SERVER-PLAN.md](SERVER-PLAN.md).

990 ₽ самостоятельно, 840 ₽ по действующему приглашению. Процент преподавателя в демо — 30%: 252 ₽ с оплаты 840 ₽. Повторное открытие оплаченного персонального приглашения не создаёт новый платёж. Обществознание переключается в кабинете, но покупка и приглашения отключены до подключения его банка.

Кабинеты обновляются при изменении данных в соседней вкладке. Черновики разделены по ученикам; после сдачи черновик удаляется. Проверка работы без сочинения завершается автоматически. Сочинение меньше 150 слов получает 0 по К1–К10. Учитель видит полные условия части 1, ответы и объяснения.

Формат и критерии взяты из приложенного прототипа и требуют сверки учителем с официальными материалами перед использованием для подготовки. 30 вариантов, настоящая статистика, платежи и ИИ ещё не подключены.
